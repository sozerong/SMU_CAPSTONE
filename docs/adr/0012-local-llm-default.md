# ADR-0012. 기본 생성 모델을 로컬 오픈소스(qwen2.5:7b)로: 폐쇄망 전제

- 상태: Accepted
- 날짜: 2026-11-03
- 프로젝트: VCC
- 코드: `GragpRAG/generate.py`, `GragpRAG/eval_models.py`

## 맥락

생성 단계는 gpt-4 API 를 썼다. 공공·금융처럼 데이터가 외부로 나갈 수 없는 망에서는
외부 API 를 쓸 수 없다. 로컬 모델로 바꾸려면 "후보 안에서만 생성한다"는 이 파이프라인의
핵심 규칙이 로컬 모델에서도 지켜지는지 먼저 재야 한다.

## 측정

**같은 입력**으로 비교한다. 과거 gpt-4 실행 기록(`eval/grounding_ab_raw_*.jsonl`)에서
고유한 (질문, 후보 목록) 9쌍을 뽑아 로컬 모델에 그대로 넣었다. 바뀌는 변수는 모델과 디코딩 방식뿐이다.

- 로컬: 9쌍 × 10회 = 모델·모드당 90호출, temperature 0.3, 워밍업 1회 제외
- gpt-4: 저장된 원문 78건 (같은 9쌍, 쌍당 3~19건)
- 하드웨어: Ryzen 7 7800X3D, RTX 4070 SUPER 12GB, Ollama 0.40.14 (docker)
- 판정: `grounding.validate_answer` (lenient, 런타임 규칙). 구간은 95% Wilson

| 모델 | 모드 | 답변 거부 | 후보 밖 (항목, lenient) | 재료 경로 | 스키마 실패 | 지연 p50 / p95 |
|---|---|---|---|---|---|---|
| gpt-4 (저장 원문) | free | 1/78 | 1/386 **0.3%** [0.1, 1.5] | 0/187 | 0/78 | - |
| **qwen2.5:7b** | structured | 2/90 | 2/304 **0.7%** [0.2, 2.4] | 2/128 | 0/90 | 2.17s / 4.36s |
| qwen2.5:7b | free | 2/90 | 0/292 0.0% [0.0, 1.3] | 0/114 | **2/90** | 2.09s / 4.11s |
| exaone3.5:7.8b | structured | 12/90 | 12/360 **3.3%** [1.9, 5.7] | 10/159 | 0/90 | 2.96s / 3.63s |
| exaone3.5:7.8b | free | 18/90 | 19/355 5.4% [3.5, 8.2] | 13/151 | 0/90 | 2.70s / 3.65s |
| exaone3.5:2.4b | structured | 72/90 | 228/448 50.9% | 167/200 | 0/90 | 1.43s / 1.72s |

원본: `eval/model_compare_*.json`, 표는 `python GragpRAG/eval_models.py table`.

## 결정

**기본 모델을 qwen2.5:7b, 기본 디코딩을 구조화 출력으로 둔다.** (`LLM_PROVIDER`, `LLM_MODEL` 로 교체 가능)

- qwen2.5:7b 의 후보 밖 생성률은 gpt-4 와 **구별되지 않는다** (구간 겹침).
- exaone3.5:7.8b 는 gpt-4 와 구간이 겹치지 않게 높다. 대부분 재료 경로이고, 노이즈 섞인 후보
  `멜로 딸기` 를 `멜론 딸기` 로 "고쳐" 쓰는 유형이 가장 많았다 (free 11회).
- exaone3.5:2.4b 는 가장 빠르지만 절반이 후보 밖이라 이 용도에 못 쓴다.

구조화 출력을 기본으로 둔 이유는 스키마 실패 감소가 **입증돼서가 아니다.** 0/90 vs 2/90 은
구간이 겹친다. 다만 실패가 한쪽(free)에서만 났고, 그 원인이 JSON 중간에 중국어로 넘어가는
코드 스위칭이었다. 그리고 구조화 출력이어야 항목 수(3~5)를 스키마로 강제할 수 있다.

## 같이 바꾼 것

| 변경 | 근거 |
|---|---|
| `num_predict=768`, 클라이언트 타임아웃 60s | 구조화 출력 1회가 **491.65s** 걸렸다. JSON 이 닫힌 뒤에도 디코딩이 서버 상한(40,960 토큰)까지 이어졌다 (Ollama 로그 `truncated = 1`). 나머지 539회의 최댓값은 5.50s |
| 스키마 `minItems` 1 → 3 | 프롬프트는 3~5개를 요구하는데 2개짜리 답이 통과했다 (qwen 2/90) |
| `OLLAMA_URL` 명시 권장 | 한 호스트에 Ollama 가 둘(네이티브 0.4.1, docker 0.40.14)이었다. 0.4.1 은 JSON 스키마 `format` 을 HTTP 400 으로 거부한다. `localhost` 가 어느 쪽으로 가는지는 보장이 없다 |

위 비교 표는 이 변경 **전에** 잰 값이다. 질의 서비스 측정(ADR-0011)은 변경 후다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| gpt-4 유지 | 폐쇄망 전제를 만족하지 못한다 |
| exaone3.5:7.8b | 한국어 모델이라 후보였으나 후보 밖 생성률이 gpt-4 보다 구별되게 높았다 |
| 더 큰 로컬 모델 (14B 이상) | 12GB GPU 에 4bit 로도 여유가 적다. 7B 가 gpt-4 와 구별되지 않으므로 키울 근거가 없다 |

## 한계

- 입력 9쌍이다. 재료 4쌍, 메뉴 5쌍.
- lenient 기준은 "후보 단어 + 다른 단어"(예: `쫀득 코코넛 크림`)를 통과시킨다. strict 기준은
  qwen 12.2%, gpt-4 42.5%, exaone 95.8% 로 순위가 다르게 나온다. strict 는 조합 생성을
  위반으로 세므로 런타임 기준으로 쓰지 않지만, 숫자는 같이 남긴다.
- 답변 설명문의 품질(사실성, 자연스러움)은 재지 않았다.
